# Nod uplift — 2026-09-22

Implemented against baseline `3e3d086` (version 1.0.1), following the [project review](2026-09-22-project-review.md). The review remains a historical record of the original checkout. This document describes the resulting implementation, verification, and remaining release acceptance work. No release, deployment, or production notification was performed.

Three parallel implementation/review workstreams covered server/protocol, shared runtime/TUI, and Apple/FFI; the coordinating workstream covered desktop, admin, integration, and final verification. Reviewers also examined other workstreams. Independent checks caught additional snapshot-ordering, partial-enrollment, push-capability, Linux notification replacement, and private-HTTP admin issues, which were addressed before completion.

## User-visible changes

- An all-channel inbox for the selected server, local channel switching, search, and paged server history. Pending work survives history retention; clearing a channel hides handled items without deleting their history.
- Connection states distinguish connecting, reconciling, current, offline, and revoked, with last-sync information and retry feedback. Reconnects fetch missed state automatically.
- Failed decisions preserve notes and expose errors. Busy states prevent duplicate submission. Every issuer-defined option and label remains available. Notes remain optional under the existing API contract.
- Request details expose outcomes, actor/device identifiers, timestamps, expiry, server/channel context, signature provenance, and copyable request IDs. Desktop renders constrained Markdown and shows link destinations.
- Guided enrollment validates addresses and codes, supports adding another server, and accepts enrollment links. Apple registers the link scheme; desktop supports pasting a link. Enrollment remains successful if registration commits but the first inbox refresh fails.
- Per-device content hiding, per-channel mute, snooze, sound controls, and notification diagnostics. Apple preferences are server-backed so they apply to APNs; desktop controls apply locally. Desktop has local quiet hours; Apple uses system Focus schedules. Muting does not remove work or change decision eligibility.
- Notification actions fetch the authoritative request using its explicit server identity. Native menus preserve real option IDs and fall back to opening the complete request when privacy, text entry, or menu capacity requires it. Obsolete alerts are removed.
- Apple window reopening and login controls, desktop login controls, accessible desktop dialogs with focus restoration/Escape, and TUI text entry, custom-option selection, list/detail scrolling, history, and recovery.
- Remote media is opt-in and bounded by time, byte size, and decoded dimensions. Images do not delay Apple's essential alert; desktop rejects active image formats and sanitizes previews to static PNG data.
- Admin Activity & Delivery shows recent requests, receipts, push attempt state, errors, and audit health. Test requests reuse an idempotency key after an uncertain response, including when the admin page is served over private HTTP.

## Performance and operational behavior

Request hydration now loads related recipients, options, and decisions in three batched queries instead of three per request. The active-server cache supports channel switching without a full network refresh; history is cursor-paged independently of the inbox.

A synthetic 5,200-request database with 200 pending requests and a 100-item handled page returned its 300-item first page at **75.9 ms median / 80.3 ms maximum** over nine debug-build samples on the development machine. This is fixture evidence, not a production capacity guarantee or a measured before/after speedup. The first page deliberately retains all pending work and therefore has no fixed total item bound.

Push delivery uses at most four worker slots and three attempts, with bounded HTTP/outer timeouts and recovery after restart. Callbacks use at most sixteen concurrent tasks and return control to the client after the decision commits. Desktop image work is limited to four concurrent loads, 12 seconds, 8 MiB downloaded data, and bounded decoding.

## Compatibility and release acceptance

- Use matching upgraded server and clients for the v2 private signing path. Original v1 vectors and historical signatures remain verifiable. Single-recipient and issuer/admin views retain the v1 digest; multi-recipient device views omit it. Historical v1 receipts retain their original digest, including its original privacy limitations; signed evidence was not rewritten.
- Additive database migrations preserve installed credentials and signing keys. Profile migration preserves credential aliases, including Apple hardware-key identities. Tombstoned user IDs stay reserved. Back up the database and retained verification/audit material before deployment using the [deployment procedure](../deploy.md).
- The server operator still sees requests and recipients. This change does not add end-to-end encryption or make the server's verification verdict an independent trust authority.
- Push acceptance does not establish that a person saw an alert. Crash retries can duplicate delivery; collapse IDs reduce that risk. Muted/snoozed pushes are skipped and are not replayed later. Callbacks remain unsigned best effort. The callback origin allowlist is opt-in; it does not pin DNS or replace network egress policy.
- Audit archives are retained for operator-managed cleanup. Audit writes are not atomic with SQLite and do not promise power-loss durability; observed write failures make health sticky until restart. SQLite remains a single-server deployment.
- Real Windows toast display/click/remove, Linux notification-daemon behavior, locked/background iOS APNs actions, Apple VoiceOver/Dynamic Type, and login-item approval still require platform acceptance. The macOS host could not build the entire Windows dependency graph because the Windows C SDK was unavailable; the targeted API harness is narrower evidence.
- No signing/notarization, packaged release acceptance, live APNs send, production restore, commit, push, or deployment was performed in this uplift. Existing local `.work/` content was preserved.

Implementation and regression tests are the durable evidence. Temporary detailed build logs and synthetic browser screenshots live under `/private/tmp/nod-uplift-*`; they are not runtime dependencies.
