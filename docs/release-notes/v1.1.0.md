Nod v1.1.0 brings reliable delivery, refreshed admin and Apple interfaces, and
one optional signed answer value in a single release. Ordinary cards retain
their existing API and signing bytes. The current logo stays unchanged.

## What's changed

- **Reliable edges:** create, answer, cancel and expiry events enter a committed
  lifecycle outbox. Optional NATS publishing runs after commit without waiting
  on the broker in HTTP handlers. Callbacks retry durably with stable delivery
  IDs; push leases recover abandoned work, and live clients resynchronize after
  missed updates. Delivery is at-least-once: consumers must deduplicate stable
  IDs, and push collapse IDs do not guarantee exactly one notification.
- **Inset admin:** focused desktop views, a searchable revoked-token log and a
  searchable bundled emoji picker. Select-subscribed selects the right users,
  logout clears dialogs and one-time token material, and partial membership-save
  failures are surfaced rather than silently reported as success.
- **Inset Inbox on iOS and macOS:** compact decision flows with every answer
  option reachable by scrolling, including long lists in small windows.
  macOS also recovers safe GETs after transient gateway failures, coalesces
  foreground refreshes and keeps Dock badges current without replaying answers.
- **One signed value:** add one choice, number, date or UTC-minute control with
  a valid issuer-supplied default, alongside optional notes. Updated Apple apps
  edit all four types; value-card notifications open the app before answering.
  The TUI edits choices and directs number/date/time requests to an updated
  Apple app. Desktop clients provide safe open/update guidance without submitting
  unsupported value cards; older clients reject unsupported submissions safely.

## Small issuer example

Add this optional member to an otherwise ordinary create-request body:

```json
{
  "answer_field": {
    "kind": "number",
    "label": "Quantity",
    "default": { "kind": "number", "decimal": "4" }
  }
}
```

Numbers use canonical decimal strings. Value cards use `nod-request-v3` and
`nod-decision-v2`, binding the selected `answer_value` and notes into the signed
decision. Ordinary cards retain their previous formats. This is one control,
not a multi-field form engine; no recipient Skip action is added.

## Upgrade and distribution

Upgrade the server and standalone APNs relay together. Review the
[deployment and delivery policies](../deploy.md), including durable queue
backups and callback deduplication, before enabling integrations.

The public macOS distribution route is a Developer ID-signed, notarized and
stapled DMG. Windows remains an unsigned desktop ZIP. iOS direct-install
handoff is separate from the public macOS release; see the
[Apple deployment guide](../../client/nod-apple/docs/APPLE.md).
