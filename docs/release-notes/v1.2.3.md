Nod v1.2.3 makes background connection recovery quieter on macOS and iOS.

## Changes since v1.2.2

- Background sync, refresh, network, timeout and server errors appear in the
  existing server connection status instead of opening an alert. The status
  clears after a later successful refresh for that server.
- Failed answers, acknowledgements, enrollment, subscription and device-management
  actions still show alerts. Background recovery cannot dismiss an action error,
  and repeated runtime snapshots cannot reopen a dismissed action alert.
- Invalid sessions still offer re-enrollment. Notification permission, signing
  and changed-request alerts remain visible.
- iOS background fetch reports whether its refresh succeeded, independently of
  any pending action alert.
- Regression tests cover error ownership, recovery and startup completion,
  including refresh calls that overlap the initial connection.

No server API, request-digest, decision-signing or automatic acknowledgement
behaviour changes.
